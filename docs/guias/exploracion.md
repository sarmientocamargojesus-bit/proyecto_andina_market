# Guía: la interfaz de GitHub (capítulo 03)

## Mapa de navegación de un repositorio

| Pestaña | Para qué sirve | En este proyecto |
|---|---|---|
| **Code** | Archivos, ramas, README, clonar | `main`, README y estructura de carpetas |
| **Issues** | Tareas, errores y mejoras | #1–#8 (cap. 13), #32 (cap. 29) |
| **Pull requests** | Proponer, revisar y fusionar cambios | Desde el #9 (cap. 14) |
| **Actions** | Workflows y sus ejecuciones | CI, PR, Pages, Release, manual, programado |
| **Projects** | Tableros de trabajo | "Andina Market 360" (ver [projects.md](projects.md)) |
| **Security** | Políticas, alertas, reporte privado | `SECURITY.md`, Dependabot |
| **Insights** | Actividad, contribuidores, tráfico | Gráfico de commits por capítulo |
| **Settings** | Configuración (solo administradores) | Pages, reglas de `main`, seguridad |

Atajos útiles: `t` (buscar archivo), `.` (abrir en el editor web), `y` (enlace permanente al commit), `?` (lista de atajos).

## Comparación de repositorios públicos

| Aspecto | `octocat/Hello-World` | `octocat/Spoon-Knife` |
|---|---|---|
| Propósito | Repositorio mínimo de ejemplo | Repositorio para practicar *fork* y PR |
| Contenido | Solo un README | `index.html`, `styles.css`, README |
| Uso en el cuaderno | Ver la estructura más simple posible | Practicar fork (cap. 16) sin molestar a nadie |
| Forks / estrellas | Muchos: cualquiera los usa para aprender | Muchísimos forks: está hecho para eso |

## Seguimiento de un Issue público: `cli/cli#14692`

Se observó el Issue público **`cli/cli#14692`** del proyecto GitHub CLI **sin comentar ni reaccionar**, solo para estudiar:

- Cómo está redactado: descripción, pasos para reproducir y versión.
- Qué etiquetas le asignan los mantenedores y cómo se triagea.
- Cómo se enlaza con el PR que lo resuelve (`Fixes #…`).

Para seguirlo sin intervenir: botón **Subscribe** del Issue (notificaciones) y quitarlo al terminar la práctica.
